# DarkPrince VPN — Linux

Клиент к той же связке, что и остальные приложения: панель **Remnawave** и
кабинет **Bedolaga**. Те же эндпоинты, тот же формат подписки, тот же учёт
устройств — и тот же интерфейс, что у версии для Windows.

Внутри — движок на Rust и оболочка на Tauri. Разбор подписки и сборка конфига
ядра общие с Windows-версией слово в слово: панель отдаёт один формат, и
расходиться этим двум клиентам нельзя. Различается только системная часть.

## Два режима

| | Системный прокси | Весь трафик |
|---|---|---|
| Права | не нужны | пароль один раз при подключении |
| Браузеры | да | да |
| Программы со своим сетевым стеком (игры, торренты) | нет | да |
| Консольные программы | нет | да |
| Как работает | правит настройки прокси GNOME и KDE | TUN-интерфейс забирает трафик системы и отдаёт его в SOCKS ядра |

Про режим прокси стоит сказать честно: единой системной настройки в Linux не
существует. Рабочие столы держат свою, а консольные программы смотрят на
переменные окружения и о настройках рабочего стола не знают. Поэтому режим
прокси покрывает браузеры и оконные программы, а всё остальное — задача режима
«весь трафик».

## Про права

Windows-версия перезапускает себя от администратора целиком. Здесь так не
делается и не нужно: TUN-интерфейс создаётся **на имя текущего пользователя**,
поэтому мост открывает его без всяких прав и остаётся обычным потомком
приложения — а значит, гибнет вместе с ним. Через `pkexec` выполняется только
то, что действительно требует прав: создание интерфейса и правка маршрутов.
Пароль спрашивается один раз на подключение, а не на каждую команду.

## Про зацикливание трафика

Главная тонкость режима «весь трафик». Ядро ходит к серверу через обычную
сеть, и если весь трафик уйдёт в туннель, оно начнёт слать пакеты в
собственный туннель. Поэтому перед поднятием туннеля приложение:

1. находит основной шлюз (`ip -j route` — машинный формат, не зависящий ни от
   языка системы, ни от версии iproute2);
2. достаёт из конфига адреса **всех** серверов и разрешает их в IP, пока DNS
   ещё прямой;
3. прокладывает до каждого отдельный маршрут через физический шлюз;
4. и только потом направляет остальной трафик в туннель — двумя половинками
   `0.0.0.0/1` и `128.0.0.0/1`, чтобы не трогать исходный маршрут по умолчанию
   и не восстанавливать его потом.

Порядок проверяется тестом: маршрут до сервера обязан лечь раньше перехвата.

## Окно, трей и выход

Три разных действия разведены явно, как и на Windows:

* **Свернуть** — обычное сворачивание, приложение остаётся в трее;
* **Крестик** — спрашивает: свернуть в трей или выйти совсем;
* **Выход** — снимает соединение, возвращает системный прокси, убивает своё
  ядро и мост, освобождает порты и закрывается.

Приложение пускает себя в одном экземпляре: повторный запуск показывает уже
работающее, а не вешает в трей второй значок.

## Установка на Arch

Правильный способ — собрать пакет, тогда файлы попадают под учёт pacman:

```bash
git clone https://github.com/DarkPrince922/DarkPrinceVpnLinux
cd DarkPrinceVpnLinux/packaging
makepkg -si
```

Зависимости: `webkit2gtk-4.1`, `libayatana-appindicator`, `polkit`, `iproute2`.
Ядро Xray и мост tun2socks скачиваются при сборке — в репозитории их нет.

## Другие дистрибутивы

В разделе Releases лежат **AppImage** (ничего ставить не нужно) и **.deb**.

## Сборка из исходников

```bash
bash scripts/fetch-cores.sh src-tauri/core
cd src-tauri && npx @tauri-apps/cli@^2 build
```

Нужны Rust, Node и системные пакеты для Tauri: `webkit2gtk-4.1`,
`libayatana-appindicator`, `librsvg`.

Тесты движка идут отдельно и не требуют ни Tauri, ни прав:

```bash
cd engine && cargo test
```

## Структура

```
engine/src/
  subscription.rs   разбор подписки панели      — общий с Windows
  config.rs         сборка конфига ядра         — общий с Windows
  proxy.rs          режим прокси: GNOME и KDE
  tun.rs            режим «весь трафик»: интерфейс, маршруты, polkit
  sys.rs            запуск программ, порты, журнал
  lib.rs            общий выключатель
src-tauri/src/main.rs   оболочка: команды, значок в трее, выход
ui/                     интерфейс — тот же, что в Windows-версии
packaging/              PKGBUILD и ярлык
```

## Если что-то не работает

Приложение пишет журнал в `~/.local/share/ru.dprince.vpn/app.log` — там видно,
какой конфиг ушёл ядру, какой шлюз найден и почему не поднялся туннель. Рядом
лежат `xray.log` и `tun2socks.log` с выводом самих программ.
