# DarkPrince VPN — Linux

Консольный клиент к той же связке, что Android- и iOS-приложения: панель
**Remnawave** и кабинет **Bedolaga**. Те же эндпоинты, тот же формат подписки,
тот же учёт устройств.

> **Статус: собирается и проверен автотестами, на живой подписке не запускался.**
> Тесты поднимают настоящее ядро Xray, гоняют через него трафик и проверяют
> TUN-интерфейс с маршрутами — но всё это против локальных заглушек. С
> настоящим сервером Remnawave клиент ещё не работал.

## Два режима

| | что делает | нужны ли права |
|---|---|---|
| **proxy** | ядро слушает SOCKS5 `127.0.0.1:10808` и HTTP `127.0.0.1:10809`; приложения направляются туда вручную | нет |
| **tun** | поднимает TUN-интерфейс, весь трафик системы идёт через туннель | да, `CAP_NET_ADMIN` |

Режим `proxy` не требует ничего: его можно запускать обычным пользователем.
Режим `tun` правит таблицу маршрутов, поэтому нужен root или служба с
`CAP_NET_ADMIN`.

## Как устроено

```
   трафик системы            приложения (режим proxy)
        │                            │
     TUN-интерфейс                   │
        │                            ▼
   tun2socks ────────►  SOCKS 127.0.0.1:10808  ────►  Xray-core  ────►  сервер
```

Ядро Xray подключается как обычная Go-библиотека, а не отдельным процессом или
бинарником, — на Linux оно родное. Всё собирается в один самодостаточный файл:
ни внешних зависимостей, ни докачки ядра при установке.

Один и тот же бинарник — и служба, и управление ею. Служба держит ядро с
туннелем, команды общаются с ней через unix-сокет.

## Сборка

Нужен **Go 1.26** или новее (этого требует свежий `xray-core`).

```bash
go build -o darkprince .
sudo install -m755 darkprince /usr/local/bin/
```

## Установка службы

```bash
sudo install -m644 packaging/darkprince-vpn.service /etc/systemd/system/
sudo ./scripts/download-geodata.sh        # см. «Геоданные» ниже
sudo systemctl enable --now darkprince-vpn
```

Управляющий сокет создаётся с правами `0660`, поэтому команды выполняются от
root (`sudo darkprince …`). Режим `tun` всё равно требует привилегий, так что
отдельной группы доступа пока не заводим.

Для режима `proxy` служба не нужна системной — её можно запустить под своим
пользователем, тогда сокет и состояние лягут в домашний каталог:

```bash
darkprince daemon &
darkprince connect --mode proxy
```

## Использование

```bash
darkprince login                  # вход через Telegram
darkprince login --email you@example.com
darkprince refresh                # загрузить серверы подписки
darkprince servers                # список узлов
darkprince use 3                  # выбрать узел
darkprince connect --mode tun     # или --mode proxy
darkprince status
darkprince disconnect
```

Без аккаунта кабинета можно работать по ссылке, которой с вами поделились:

```bash
darkprince link https://sub.example/abcdef
darkprince refresh
darkprince connect
```

В режиме `proxy` направьте приложения на прокси:

```bash
export http_proxy=http://127.0.0.1:10809 https_proxy=http://127.0.0.1:10809
```

## Геоданные

Конфиги панели Remnawave обычно содержат правила вида `geosite:category-ads-all`
или `geoip:private`. Для них ядру нужны файлы `geoip.dat` и `geosite.dat`, и
**без них оно отказывается стартовать целиком** — не игнорирует правило, а
роняет весь конфиг. Поэтому:

```bash
sudo ./scripts/download-geodata.sh
```

Если файлов нет, служба скажет об этом при запуске. Пока подписка не пользуется
такими правилами, всё работает и без них.

## Чего здесь нет

Кабинета: баланса, тарифов, покупки, промокодов. В консоли им не место —
оплата всё равно требует браузера, а тарифы удобнее выбирать в боте или
мобильном приложении. Клиент занимается только VPN: вход, подписка, серверы,
подключение.

## Ограничения

* Только IPv4 в обходных маршрутах. Адреса IPv6 в туннель заворачиваются, но
  отдельного маршрута мимо туннеля для них не строится.
* Раздельного туннелирования по приложениям нет. На Linux это делается через
  cgroup и правила фаервола, а не средствами клиента.
* Счётчик нисходящего трафика ядро досчитывает при закрытии соединения,
  поэтому на долгих keep-alive сессиях он какое-то время отстаёт.

## Структура

```
main.go                 точка входа
internal/
  xray/       модель узла, разбор подписки, сборка конфига ядра
  api/        клиент Cabinet API, скачивание подписки
  store/      состояние, токены, кэш подписки
  engine/     запуск ядра, режимы proxy и tun, маршруты
  ipc/        протокол между CLI и службой
  cli/        команды
  daemon/     служба
packaging/    unit для systemd
```
